================================================================================
ABSTRACT
================================================================================

Scoratis (Socratic-AI) is an AI-powered Socratic learning platform that combines
an immersive 3D virtual museum/gallery environment with an intelligent AI tutor
that teaches through guided questioning rather than direct answers. Named after
Socrates, the platform serves as "The Ultimate Socratic Architect" -- an AI
mentor that builds deep, foundational understanding through guided Socratic
discovery.

The platform features a Three.js-powered 3D gallery containing 10 subject
channels (Physics, Chemistry, Biology, Mathematics, Computer Science, English,
History, Philosophy, Psychology, and Economics) displayed as interactive portals
on gallery walls. Users navigate the space as an avatar and can approach a
"Socrates" statue or any subject portal to begin a learning session. Through a
chat interface, users interact with an AI tutor that follows a strict 6-step
scaffolding methodology (Assess, Foundation, Build, Deepen, Apply, Verify) and
never directly provides answers -- instead guiding students to discover answers
themselves through reasoned inquiry.

The system incorporates advanced features including:
- Agentic RAG (Retrieval-Augmented Generation) with LangGraph-based reasoning
- Hybrid search combining semantic vector search and keyword search with
  Reciprocal Rank Fusion (RRF) scoring
- Automatic AI-generated video animations (Manim) triggered by conversation
  depth
- Multi-LLM support supporting 100+ providers through LiteLLM (local Ollama,
  OpenAI, Anthropic, Google, Groq, etc.)
- Document upload and personal knowledge base with semantic search
- Journal system with folder organization and tagging
- Subject-specific guardrails and contextual tutoring
- Text-to-speech with multiple tutor voice personas
- Encrypted API key storage for secure cloud provider access

================================================================================
PROBLEM STATEMENT
================================================================================

Traditional educational technology platforms suffer from several fundamental
limitations that Scoratis was built to address:

1. PASSIVE LEARNING PARADIGM
   Most EdTech platforms are information-delivery systems -- they lecture,
   present content, and quiz students. This passive approach leads to surface-
   level retention rather than deep conceptual understanding. Students consume
   content but often fail to develop the critical thinking and reasoning skills
   necessary for true mastery.

2. ONE-SIZE-FITS-ALL APPROACH
   Conventional platforms treat all learners identically, ignoring individual
   knowledge gaps, learning pace, confusion signals, and personal context. A
   student struggling with a concept receives the same explanation as one who
   has already grasped it.

3. LACK OF PERSONALIZATION
   Students cannot bring their own materials, notes, or prior work into most
   tutoring systems. The AI has no awareness of what the student has previously
   studied, what documents they've referenced, or where their specific
   misunderstandings lie.

4. ABSTRACT CONCEPTS WITHOUT VISUAL GROUNDING
   Complex scientific and mathematical concepts are often presented as text or
   static images, failing to provide dynamic visual and spatial mental models
   that aid comprehension.

5. LLM AVAILABILITY AND PRIVACY CONCERNS
   Many AI tutoring systems require cloud API access, creating dependencies on
   internet connectivity, API costs, and data privacy concerns. Students and
   institutions need the flexibility to run systems locally when desired.

6. LOSS OF THE SOCRATIC METHOD
   Modern AI tutors often default to direct answers when prompted, undermining
   the pedagogical value of guided discovery. There is a need for systems that
   enforce the Socratic method as a strict constraint rather than an optional
   style.

Scoratis was built to solve these challenges by inverting the traditional
EdTech paradigm: instead of delivering information, it guides students through
active discovery; instead of a generic experience, it provides personalization
through RAG-based context from the student's own materials; instead of static
content, it generates dynamic visual animations; and instead of requiring cloud
access, it supports fully local operation through Ollama.

  +-- Chat Interface                        +-- Agentic RAG System
  +-- Dashboard/Journals                    +-- LangGraph State Machine
  +-- VideoVault                            +-- Multi-LLM Service (LiteLLM)

  +-- Redis 7 (Celery/Cache)                +-- Encryption Service

Infrastructure:
  - Docker Compose runs PostgreSQL (with pgvector) and Redis as containers
  - Frontend and Backend run as local development servers (via start_dev.sh)
  - Nginx serves as a reverse proxy for production deployment

--------------------------------------------------------------------------------
MODULE BREAKDOWN
--------------------------------------------------------------------------------

1. AGENTIC REASONING SYSTEM (backend/services/agent/)
   
   This is the core intelligence of the system, implementing a LangGraph-based
   Think -> Act -> Observe -> Verify loop with cyclical tool use.
   
   - graph.py: The ScoratisAgent class implementing the agent node, tools node,
     verification node, and refinement node with conditional routing. The agent
     maintains a Scratchpad across iterations to persist thoughts, observations,
     and plans.
   
   - tools.py: Tool registry with 11+ tools including search_knowledge_base,
     search_journals, search_past_conversations, web_search, think, plan,
     delegate, verify_response, get_learning_context, remember_discovery,
     request_clarification, and finalize_response.
   
   - orchestrator.py: Sub-agent delegation to specialized agents (Research,
     Analysis, Summary, Expert, Fact-Check) for complex queries.
   
   - verifier.py: Response quality checking before delivery to ensure the AI
     adheres to Socratic principles.
   
   - query_classifier.py: Detects trivial queries (greetings, etc.) to skip
     unnecessary tool calls and improve response time.
   
   - prompts.py: Dynamic system prompt construction with subject-specific
     contexts and scaffolding guidelines.

2. RAG SERVICE (backend/services/rag_service.py)
   
   Implements hybrid RAG with semantic search (pgvector cosine similarity) and
   keyword search (PostgreSQL full-text search), fused using Reciprocal Rank
   Fusion (RRF) scoring. Features include multi-level document+chunk search,
   query reformulation via LLM, cross-encoder re-ranking, and contextual
   grouping of results.

3. MULTI-LLM SERVICE (backend/services/litellm_service.py)
   
   Universal LLM service supporting 100+ providers via LiteLLM with centralized
   error handling, validation, and timeout management. Supports local providers
   (Ollama, LM Studio, LocalAI) and cloud providers (OpenAI, Anthropic, Google,
   Groq, Together, Azure, DeepSeek).

4. EMBEDDING SERVICE (backend/services/embedding_service.py)
   
   Async embedding generation via Ollama (all-minilm model, 384 dimensions)
   with parallel batch processing for document ingestion.

5. WEB SEARCH SERVICE (backend/services/web_search_service.py)
   
   DuckDuckGo integration with automatic knowledge gap detection -- when the
   LLM indicates it doesn't know something, the system automatically triggers
   a web search to augment its knowledge.

6. MEMORY SERVICE (backend/services/memory_service.py)
   
   Short-term and long-term memory management for maintaining conversation
   context and learning history across sessions.

7. DOCUMENT INGESTION (backend/services/ingestion_service.py)
   
   Parses PDF, DOCX, TXT, HTML, and Markdown files. Implements text chunking
   with overlap and batch embedding for inclusion in the vector database.
   Processing runs as background Celery tasks.

8. GUARDRAIL SERVICE (backend/services/guardrail_service.py)
   
   Subject boundary enforcement using keyword matching and optional LLM
   classification for each of the 10 subjects. Ensures the tutor stays within
   the selected subject domain and warmly redirects off-topic queries.

9. VIDEO SERVICE (backend/services/video_service.py)
   
   AI video generation pipeline with Ollama/Smart client selection, Manim
   integration for mathematical/scientific animations, and a multi-stage
   pipeline: script generation -> voice synthesis -> rendering -> merging.

10. CONVERSATION ANALYZER (backend/conversation_analyzer.py)
    
    Tracks learning state, content richness scoring (empty/casual/exploring/
    learning/deep), concept extraction, and video trigger detection (hint,
    scaffold, reinforcement, summary triggers for automatic video generation).

11. CITATION PROCESSOR (backend/services/citation_processor.py)
    
    Handles citation formatting and rendering when the AI references uploaded
    documents, producing inline [citation:chunk_id] markers that render as
    clickable popup references in the UI.

12. ENCRYPTION SERVICE (backend/services/encryption_service.py)
    
    Fernet encryption with PBKDF2 key derivation for secure storage of cloud
    provider API keys in the database.

13. FRONTEND 3D GALLERY (frontend/src/pages/Gallery.jsx)
    
    The Three.js-powered immersive environment featuring animated character
    navigation, 10 subject portals displayed as paintings on walls, Socrates
    statue interaction, bloom post-processing effects, and session choice
    modals.

14. FRONTEND CHAT INTERFACE (frontend/src/pages/Chat.jsx)
    
    The chat interface with markdown rendering, syntax highlighting, citation
    popups, inline video cards, agentic workflow indicators, search trail
    indicators, web search progress visualization, TTS playback, and canvas
    panel for visual content.

15. FRONTEND SETTINGS (frontend/src/pages/Settings.jsx)
    
    LLM provider configuration UI supporting local and cloud provider
    management, model selection, VRAM-based recommendations, and live model
    testing.

--------------------------------------------------------------------------------
WORKFLOW
--------------------------------------------------------------------------------

USER JOURNEY:
1. Entry: User opens the application and sees the 3D gallery loading screen
   with progress tracking (backend connection, subject textures, character
   model, Socrates model, scene assembly).

2. Gallery Navigation: After loading, the user navigates the 3D hall as an
   avatar. Subject portals line both walls. The user can approach the Socrates
   statue for a general session or any subject portal for domain-specific
   tutoring.

3. Subject Selection: When approaching a subject, the user can start a new
   session or resume an existing one. The subject determines the tutor's domain
   and the system prompt used.

4. Chat Interaction: The user enters the chat interface and asks questions.
   The backend processes the request through the pipeline described below.

5. Video Generation: If the conversation reaches sufficient depth and content
   richness, a video animation is automatically generated and offered inline
   within the chat.

6. Document Upload: Users can upload documents at any time, which are processed
   in the background (parse -> chunk -> embed -> index) and become available
   for RAG searches.

AGENT PROCESSING PIPELINE (per request):
1. Query Classification: Check if the query is trivial (greeting, etc.) to
   skip unnecessary tool calls and improve response time.

2. RAG Context Retrieval: Hybrid search across uploaded documents, journals,
   and past conversations with query reformulation and RRF fusion for optimal
   relevance.

3. Subject Guardrail Check: Validate the query is within the selected subject
   domain. Off-topic queries are warmly redirected.

4. Agent Graph Execution:
   a. Agent Node: LLM decides whether to respond directly or use tools
   b. Tools Node: Execute selected tools (search, web search, think, plan,
      delegate to sub-agents)
   c. Verification Node: Check response quality against Socratic principles
   d. Refinement Node: Improve response if verification fails
   e. Loop continues until a verified final response is produced

5. Response Delivery: Stream the response to the frontend with citation
   markers, learning state updates, and optional video triggers.

KEY IMPLEMENTATION HIGHLIGHTS:

1. SOCRATIC SYSTEM PROMPT (backend/prompts.py)
   The core Socratic methodology is enforced through carefully crafted system
   prompts that include:
   - "You NEVER give direct answers -- always guide through questions"
   - "Ask exactly ONE question per response -- never more"
   - "70% knowledge anchor + 30% targeted inquiry" ratio
   - Subject-specific core topics, allowed tangents, and blocked patterns
   - 6-step scaffolding progression framework

2. AGENTIC GRAPH (backend/services/agent/graph.py)
   The LangGraph state machine implements:
   ```python
   # Simplified representation
   graph = StateGraph(AgentState)
   graph.add_node("agent", agent_node)        # LLM decision making
   graph.add_node("tools", tools_node)        # Tool execution
   graph.add_node("verify", verification_node) # Quality check
   graph.add_node("refine", refinement_node)   # Response improvement
   
   graph.set_entry_point("agent")
   graph.add_conditional_edges("agent", should_use_tools)
   graph.add_edge("tools", "verify")
   graph.add_conditional_edges("verify", passes_verification)
   graph.add_edge("refine", "agent")  # Loop back
   ```

3. HYBRID RAG WITH RRF FUSION (backend/services/rag_service.py)
   Combines semantic and keyword search:
   ```python
   # Simplified representation
   semantic_results = pgvector_cosine_search(query_vector, subject, top_k=20)
   keyword_results = postgresql_fulltext_search(query_text, subject, top_k=20)
   fused_results = reciprocal_rank_fusion(semantic_results, keyword_results)
   # RRF formula: RRF(d) = sum(1 / (k + rank(d))) for each result
   ```

4. 3D GALLERY RENDERING (frontend/src/pages/Gallery.jsx)
   Three.js scene with:
   - Animated avatar with WASD/arrow key navigation
   - 10 subject portals as interactive paintings on walls
   - Socrates statue with click interaction
   - Bloom post-processing for atmospheric lighting
   - Loading screen with asset progress tracking

5. VIDEO GENERATION PIPELINE (backend/services/video_service.py)
   Multi-stage pipeline:
   ```
   Conversation Analysis -> Content Richness Scoring -> Trigger Detection
   -> Script Generation (LLM) -> Voice Synthesis (TTS) 
   -> Manim Code Generation -> Video Rendering -> Audio Merge -> Delivery
   ```

CONCLUSION
================================================================================

Scoratis represents a significant advancement in AI-powered educational 
technology by successfully implementing the Socratic method as a core 
architectural constraint rather than an optional interaction style. The project
demonstrates that an AI system can effectively guide students through active
discovery and guided questioning, producing deeper conceptual understanding
than traditional information-delivery approaches.

KEY ACHIEVEMENTS:

1. SOCRATIC METHOD ENFORCEMENT
   The system successfully prevents the AI from giving direct answers through
   a combination of system prompt engineering, response verification nodes,
   and subject guardrails. This ensures that every interaction follows the
   pedagogical principle of guided discovery.

2. ADVANCED RAG IMPLEMENTATION
   The hybrid search architecture combining pgvector semantic search, 
   PostgreSQL full-text keyword search, and Reciprocal Rank Fusion produces
   significantly better retrieval quality than either approach alone. The
   query reformulation and cross-encoder re-ranking further improve context
   relevance.

3. AGENTIC REASONING CAPABILITIES
   The LangGraph-based state machine with Think->Act->Observe->Verify loop,
   persistent scratchpad, and sub-agent delegation enables the system to
   handle complex, multi-step queries that require diverse knowledge sources
   and reasoning strategies.

4. IMMERSIVE 3D EXPERIENCE
   The Three.js virtual museum gallery provides an engaging, spatial learning
   environment that goes beyond traditional chat interfaces, giving students
   a sense of place and exploration that enhances engagement and motivation.

5. FLEXIBLE DEPLOYMENT OPTIONS
   Through LiteLLM integration, the system supports both local (Ollama) and
   cloud (OpenAI, Anthropic, Google, etc.) providers, allowing institutions
   to choose between privacy-focused local deployment and high-performance
   cloud-based models based on their needs and resources.

6. AUTOMATIC VISUAL CONTENT GENERATION
   The conversation-driven video generation pipeline automatically creates
   Manim animations when conversations reach sufficient depth, bridging the
   gap between abstract textual explanations and concrete visual 
   understanding.

TECHNICAL OUTCOMES:

- Successfully integrated 10 subject-specific tutoring domains with 
  customized prompts, guardrails, and knowledge boundaries
- Implemented encrypted API key storage enabling secure multi-tenant cloud
  provider access
- Built a document ingestion pipeline with background Celery processing
  for PDF, DOCX, TXT, HTML, and Markdown files
- Achieved real-time learning state tracking with confusion detection,
  content richness scoring, and automatic video trigger detection
- Designed a modular architecture allowing independent scaling of services
  (RAG, agent, memory, video, etc.)

EDUCATIONAL IMPACT:

The platform addresses fundamental challenges in modern education by:
- Replacing passive consumption with active discovery and critical thinking
- Providing personalized tutoring based on each student's own materials
  and learning history
- Supporting diverse learning needs through adaptive difficulty, real-world
  analogies, and confusion-responsive behavior
- Creating visual mental models through automatic animation generation
- Building foundational understanding through the proven Socratic method

FUTURE ENHANCEMENTS:

Potential areas for future development include:
- Multi-modal input (voice, handwriting recognition)

- Integration with learning management systems (LMS)

In summary, Scoratis demonstrates that AI-powered Socratic tutoring is not

potential of combining cutting-edge AI capabilities with time-tested
